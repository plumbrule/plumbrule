# 01 首版：规范库 + 网站 + Agent 技能

> 状态：进行中（2026-11-14 开始）
> 参考：32 份规范调研报告及其摘要、优化清单（个人资料，不在本仓库；仅供参考）。

## 目标

一套通用工程规范，三种用法，同一份源文件：

- **人**：公开网站查阅，可以搜索、按主题/语言/端筛选，每条规则有固定链接。
- **Agent**：安装一个技能（Agent Skills 开放格式），Claude Code、Codex 等在写代码时按需查规则。
- **安装**：一条命令装到指定 Agent，全局或单个项目；另有离线安装包。

规范是通用的，不针对任何具体产品。

## 已确认的取舍

1. 名字：准绳 / Plumbrule（`plumbline` 已被占用，改用 `plumbrule`）。
2. 规范只取调研结论，不搬报告原文；报告附带的「给 Agent 的精简版」不用，网站和技能都从规则表生成。
3. 硬约束标准：同时满足
   - 有可靠出处（标准、官方文档、公认安全底线），或违反后果严重且公认；
   - 写得出检查方法（自动工具，或明确的人工审查点）；
   - 没有「尽量」「可行时」这类软措辞；有适用前提的，前提写进规则。

   其余都是软指导。每条另标检查方式：自动 / 半自动 / 人工。
4. 数字阈值没有出处的标「参考值」并写理由；规则里不写具体版本，版本单独记账。
5. 每件事只在一个主题里定，其他主题引用（归属表见 `rules/_归属.yaml`）。
6. 许可证统一由「27 合规隐私与许可」定口径，组件许可证以官方仓库为准；区分「独立运行的工具」和「集成进产品分发」。
7. 法律相关内容统一声明「不构成法律意见」。
8. 网站：Astro Starlight 静态站，部署到 Cloudflare Workers 静态资源（与 lumevrix 相同做法）；先中文，结构上预留英文。
9. 补充调研：边整理边写提示词（提示词和结果是个人文件，不进本仓库）。

## 源文件结构

```text
rules/
  _词表.yaml          公共词表：级别、检查方式、优先级、状态名、事故等级…
  _归属.yaml          每类事项归哪个主题
  NN-slug.yaml        每个主题一份：概述、规则、选型、反模式、来源
schema/topic.schema.json
tools/check.ts        校验：结构、编号唯一、引用的来源存在、复核日期、软措辞检查
```

规则字段：编号、标题、级别（硬约束/软指导）、检查方式（自动/半自动/人工）、怎么检查、适用范围、为什么、细则、来源、参考值说明、复核日期。

## 步骤

1. 仓库骨架：计划、格式（schema）、词表、归属表、校验脚本。
2. 逐主题整理规范（每份对照摘要并回原报告核对），同时联网核实高风险说法；按批提交。
3. 写补充调研提示词（个人文件）。
4. 生成器：规则表 → 网站页面、技能参考文件、按项目生成 AGENTS.md。
5. 网站：先出画板确认，再实现；截图与画板对照。
6. 技能与安装：Claude Code、Codex 安装目录实测；离线包。
7. 部署（等用户确认后再上线）。
