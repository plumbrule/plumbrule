# 02 维护技能与发布流程

> 状态：完成（2026-11-14）

## 目标

以后改规则、加规则、废弃规则、加主题、吸收补充调研、定期复核和发布新版本，都有固定做法。这些做法写成仓库里的维护技能 `plumbrule-maintain`，Claude Code 和 Codex 都能用，由维护者手动调用。

## 已确认的取舍

1. 维护技能放在本仓库里，不打进 npm 包。只维护一份，放在 `.agents/skills/plumbrule-maintain/`（Codex 读这里），再建一个链接 `.claude/skills/plumbrule-maintain` 指向它（Claude Code 读这里）。
2. 技能只写步骤和检查清单，细则引用 `docs/编写指南.md`，不重复抄写。
3. 已发布的规则编号不能消失，也不能复用。删除规则时，把编号写进编号台账的「已废弃」，注明替代规则和原因。网站和技能不展示已废弃的规则。
4. 版本号统一用一个发布脚本修改。部署网站和发布 npm 仍由人确认后手动执行，因为 npm 发布要本人做两步验证，还要在网页上批准。
5. 不加 CI 自动检查，以后需要时再加。

## 步骤

1. 加编号台账 `rules/_编号台账.yaml`，记下 0.1.0 已发布的全部编号；`pnpm check` 增加三项检查：
   - 已发布的编号不能消失或复用；
   - 两处版本号一致；
   - 每个主题都已放进网站侧栏的某个分组。

   同时在更新记录里把 0.1.0 标为已发布，并打上 `v0.1.0` 标签。
2. 写发布脚本 `pnpm release <版本>`：
   - 检查版本号比当前的大；
   - 检查更新记录里已经写了这个版本；
   - 统一改两处版本号；
   - 把新编号追加进台账；
   - 构建网站，打包 npm 包。

   发布脚本不负责部署、不负责发 npm，也不提交。
3. 写维护技能，按场景给出步骤和检查清单；README 里加一句指向它。
4. 演示：在临时副本里用这个技能新增一条规则，再发一个测试版本 0.1.1，全程只在本地跑，不部署、不发布、不推送。

## 实施记录

### 做了什么

- `rules/_编号台账.yaml`：记录了 0.1.0 的 1247 个编号；「已废弃」目前为空。
- `pnpm check` 新增三项检查：
  - 已发布的编号不能消失、不能复用，已废弃的要写明版本和原因，改用的规则要存在；
  - 两处版本号一致；
  - 每个主题都已放进侧栏分组。
- `pnpm release <版本>`：
  - 先检查版本号和更新记录；
  - 统一两处版本号，把标题里的「未发布」换成日期；
  - 合并编号台账；
  - 构建网站，打包 npm 包；
  - 最后打印需要手动执行的提交、部署、发布、打标签命令。
- 维护技能 `.agents/skills/plumbrule-maintain/SKILL.md`，覆盖七个场景和常见报错；`.claude/skills/plumbrule-maintain` 是指向它的链接。README 里加了维护一节。
- 更新记录把 0.1.0 标为 2026-11-14 发布；`v0.1.0` 标签打在实际发布到 npm 的那次提交上（b3f9c61）。

### 偏差

- 演示改了：原计划是「新增一条规则 + 发 0.1.1」，实际做的是「废弃一条规则 + 补充一条规则的说明 + 发 0.2.0」。原因是 Claude Code 照技能检查时发现两处问题，停下来问人：
  - 要新增的规则和 GO-013 重复；
  - 废弃规则应该升次版本号。
  这两处正是技能要拦住的情况。
- 演示中发现发布脚本有两个问题，已修：
  - 改写版本标题时会吞掉标题下面的空行；
  - 打印的 git add 命令漏了规则文件。

### 验证

- 反例测试，在临时副本里做：直接删掉一个已发布的编号、两处版本号不一致，`pnpm check` 都能报出来，悬空的引用也能报出来。
- `pnpm release` 的拒绝情况都按预期拒绝：版本号格式不对、版本号不比当前大、更新记录里没写这个版本。
- Claude Code 实测，在 git worktree 临时副本里：
  - 按技能废弃了 GO-002，在台账里登记，并写了更新记录；
  - 在 GO-013 里补了说明；
  - `pnpm release 0.2.0` 校验通过（1246 条规则），网站构建成功，npm 包打包成功；
  - 构建出的 Go 主题页里已经没有 GO-002。

  演示副本已删除，没有提交。
- Codex 实测：在只读沙箱里，能找到技能并正确说出废弃规则的步骤。

### 没做的事

- CI 自动检查：按约定不做。
- 网站上的「已废弃编号」提示：现在已废弃的编号在网站上没有任何提示，打开旧链接只会落到主题页顶部。以后真的废弃了规则，再考虑在主题页底部列出「已废弃编号 → 改用」。
