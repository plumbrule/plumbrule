# 02 维护技能与发布流程

> 状态：进行中（2026-11-14 开始）

## 目标

以后改规则、加规则、废弃规则、加主题、吸收补充调研、定期复核和发布新版本，都有固定做法。这些做法写成仓库里的维护技能 `plumbrule-maintain`，Claude Code 和 Codex 都能用，由维护者手动调用。

## 已确认的取舍

1. 维护技能放在本仓库里，不打进 npm 包。只维护一份，放在 `.agents/skills/plumbrule-maintain/`（Codex 读这里），再建一个链接 `.claude/skills/plumbrule-maintain` 指向它（Claude Code 读这里）。
2. 技能只写步骤和检查清单，细则引用 `docs/编写指南.md`，不重复抄写。
3. 已发布的规则编号不能消失，也不能复用。删除规则时，把编号写进编号台账的「已废弃」，注明替代规则和原因。网站和技能不展示已废弃的规则。
4. 版本号统一用一个发布脚本修改。部署网站和发布 npm 仍由人确认后手动执行，因为 npm 发布要本人做两步验证，还要在网页上批准。
5. 不加 CI 自动检查，以后需要时再加。

## 步骤

1. 加编号台账 `rules/_编号台账.yaml`，记下 0.1.0 已发布的全部编号；`pnpm check` 增加三项检查：
   - 已发布的编号不能消失或复用；
   - 两处版本号一致；
   - 每个主题都已放进网站侧栏的某个分组。

   同时在更新记录里把 0.1.0 标为已发布，并打上 `v0.1.0` 标签。
2. 写发布脚本 `pnpm release <版本>`：
   - 检查版本号比当前的大；
   - 检查更新记录里已经写了这个版本；
   - 统一改两处版本号；
   - 把新编号追加进台账；
   - 构建网站，打包 npm 包。

   发布脚本不负责部署、不负责发 npm，也不提交。
3. 写维护技能，按场景给出步骤和检查清单；README 里加一句指向它。
4. 演示：在临时副本里用这个技能新增一条规则，再发一个测试版本 0.1.1，全程只在本地跑，不部署、不发布、不推送。
